# Quest Sorceress — App Spec

## 1. App overview

- **App name:** Quest Sorceress
- **One-line pitch:** A gamified to-do app that automatically generates daily quests and lets you dress up your own customizable sorceress as you complete them.
- **Target user:** People who find plain to-do lists demotivating, and who find deciding what to do its own source of friction.
- **Problem it solves:** The app removes the blank-page problem by generating the day's tasks itself, instead of leaving the user to fill in an empty list.
- **Platform(s):** Web (responsive, browser-based) for v1; native iOS/Android apps are a later phase.
- **Success looks like:** A user completes at least 3 generated quests a day, 5 days a week, by their second week using the app.
- **Visual style:** Fantasy/nature theme — glowing vines, gold ornate borders, warm forest lighting (reference images to follow).

## 2. Core user flows

### Flow 1: Receive and complete a generated quest

1. The app's quest engine generates 3 to 5 quests each morning, pulled from a curated library filtered by the categories and difficulty the user chose in Quest Preferences.
2. Quests appear on Home automatically — the user does not type or create them.
3. User taps a quest to mark it complete: it moves to Completed on Home and counts toward today's streak; a short completion animation plays.
4. User can dismiss a quest they don't want to do; a different eligible quest from the library takes its place, and the dismissed quest becomes eligible to reappear again after 14 days.

### Flow 2: Daily streak

1. User completes at least one quest today.
2. The streak counter on Home increments by one.
3. Missing a full day resets the streak to zero.

### Flow 3: Unlock an item at a streak milestone

1. User's streak reaches a weekly milestone (7, 14, 21 days, and so on).
2. A milestone screen shows the newly unlocked item or spell.
3. User can equip the new item on their avatar immediately.

## 3. Data model

| Entity | Key fields | Belongs to or relates to |
|---|---|---|
| **User** | email, displayName, settingPreferences (multi-select: home, gym, outdoors, office/desk, school, park, mall), categoryPreferences (multi-select: fitness, mindfulness, productivity/chores, learning, fun activities, random activities), difficultyPreference, createdAt | none |
| **QuestTemplate** | title, description, category, difficulty, requiredSetting | none |
| **DailyQuest** | date, status (pending, completed, dismissed), dismissedAt | belongs to User and QuestTemplate |
| **Item** | name, type, artAssetRef, unlockAtStreakWeeks | none |
| **UserItem** | owned, equipped | belongs to User and Item |

**Notes:**

- QuestTemplate rows are the fixed curated library — nothing is generated by AI; DailyQuest just assigns an existing template to a user for a given day.
- `requiredSetting` narrows which templates are eligible for a user based on their `settingPreferences` (for example, a template tagged Gym is never assigned to a user who hasn't selected Gym).
- `unlockAtStreakWeeks` on Item sets which weekly streak milestone (1 week, 2 weeks, and so on) unlocks that item — **no XP is involved**.
- A dismissed DailyQuest's template becomes eligible to be assigned again 14 days after `dismissedAt`.
- `email` must be unique per User.

## 4. Screens and navigation

| Screen | Purpose | Links to |
|---|---|---|
| **Home** | Today's generated quests and streak counter | Quest Detail |
| **Quest Detail** | View or complete a quest (no manual creation) | Home |
| **Quest Preferences** | Choose the categories and difficulty mix the generator draws from | Home |
| **Avatar** | View sorceress and equip owned items | Inventory |
| **Inventory** | List of owned items and spells | Avatar |
| **Settings** | Account, sign out | Home |

**Entry point:** Home
**Navigation style:** Left sidebar on desktop, collapsing to a bottom bar on narrow (mobile web) viewports.

## 5. Auth and permissions

- **Who can use the app:** Anyone; each user only ever sees their own quest data. Sharing (a link, or today's progress) is a separate, user-initiated action — see section 6.
- **Sign-in method:** Email and password, or Google sign-in.
- **Roles:** Single role — every user only ever sees their own data, no admin role in v1.

| Role | Can do | Cannot do |
|---|---|---|
| User | Complete or dismiss own quests, set own preferences, equip own items | View or edit another user's quests or items |

**Rule applied:** every Quest and UserItem record is scoped to owner equals current user, **enforced server side, not just hidden in the UI**.

## 6. Integrations and third-party services

| Service | Used for | Have an account |
|---|---|---|
| Web Share API (built into the browser) | Sharing the app link | No account needed |

No payment, analytics, or AI-generation integrations in v1 — every quest comes from the fixed curated library in section 3.

## 7. Non-functional requirements

- **Expected users at launch:** Under 100 (friends and family beta).
- **Offline behavior:** Already-generated quests remain viewable and completable offline (service worker / PWA caching); syncs when back online.
- **Data sensitivity:** None — no payment or health data collected.
- **Performance target:** Home screen with today's quests loads in under 1 second.
- **Must support:** Latest two versions of Chrome, Safari, Firefox, Edge.
- **Compliance:** None known to apply.
- **Environments:** Separate dev and production Base44 projects; never test against real user data.
- **Inclusivity:** Quest content, categories, and difficulty are identical for every user — no gender-specific variants; avatar appearance is a separate cosmetic choice with no effect on gameplay.

## 8. Scope: in vs out for v1

**In scope (v1):**

- Daily auto-generated quests (3 to 5 per day) drawn from the fixed library
- Complete or dismiss a quest
- Setting-based quest filtering (home, gym, outdoors, office/desk, school, park, mall)
- Basic avatar customization (equip owned items)
- Daily streak counter
- Streak-milestone avatar/item unlocks (weekly)
- Quest preferences (categories, difficulty, setting)
- Sharing the app link via the browser's native share sheet

**Out of scope (later):**

- Native iOS/Android apps
- Multiplayer, guilds, friends
- In-app purchases
- Leaderboards
- User-authored custom quests
- AI-generated quest content (every quest comes from the fixed library)

## 9. Acceptance criteria

- A new user sees their first set of generated quests immediately after choosing categories, difficulty, and setting, with no crashes.
- Completing a quest marks it Completed on Home and updates today's streak immediately.
- Dismissing a quest removes it from Home, a different eligible quest from the library takes its place in the same session, and the dismissed quest does not reappear for 14 days.
- A quest tagged for a setting the user hasn't selected (for example Gym) is never shown to a user who only selected Home.
- Reaching a weekly streak milestone unlocks a new avatar item and shows the unlock screen.
- A logged-out user, or a different logged-in user, cannot view another user's quests — checked at the API level, not just hidden in the UI.
- Streak resets to 0 if no quest was completed the previous full day.
- Core flow (view then complete a generated quest) works with the browser offline, then syncs once reconnected.
